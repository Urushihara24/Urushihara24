## 🧭 About me

I'm a **QA Engineer** working across the full product path — **UI → API → database → logs → integrations → failure recovery → release decision**.

My strongest area is production-oriented manual QA with technical diagnostics: payments, authorization, state transitions, mobile/web behavior, third-party integrations and backend failures. I use Python for API automation, test tooling and production automation projects.

> **Good testing is not about clicking through every screen.**  
> It's about understanding what can break — and collecting enough evidence to prove what actually broke.

## 🧩 How I investigate failures

```text
Understand product and business risk
                ↓
Model critical paths / state transitions
                ↓
Reproduce and isolate the failing layer
                ↓
Collect UI + API + DB + logs evidence
                ↓
Build and verify a root-cause hypothesis
                ↓
Retest the fix + affected regression
                ↓
Make a release decision
```
