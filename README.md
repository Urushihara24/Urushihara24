## 🧭 About me

I'm a **QA Engineer** focused on understanding how a product actually works — from the interface down to APIs, databases, logs and integrations.

My main experience is **Web, Mobile, REST API and backend testing**, especially in fintech and crypto products. I enjoy technical investigation: reproduce the failure, isolate the layer, collect evidence and understand what actually happened.

Right now I'm moving deeper into **Python, test automation and backend development**. GitHub is where I keep the work that best shows how I think and test.

> **Good testing is not about clicking through every screen.**  
> It's about understanding what can break — and proving what actually broke.

## 🧩 How I approach QA

```text
Understand the product
        ↓
Model the risks
        ↓
Test the critical paths
        ↓
Investigate failures
        ↓
Collect technical evidence
        ↓
Find the cause, not only the symptom
```

<details>
<summary><b>More about my approach</b></summary>

<br>

- **What can fail?** — business risks, integrations, state transitions and edge cases.
- **Where did it fail?** — UI, API, database, asynchronous processing or external integration.
- **Why did it fail?** — logs, requests, responses, database state and reproducible evidence.

</details>
